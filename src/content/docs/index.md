## takt — AIエージェントを指揮するオーケストレーションツール

**takt**（タクト）は、AIコーディングエージェントをYAMLベースのパイプラインで統制し、再現性のある開発ワークフローを実現するオーケストレーションツールです。nrslib（成瀬允宣）によって開発され、MITライセンスで公開されています。

### なぜtaktが必要なのか

AIコーディングエージェントは強力ですが、そのまま使うと以下の問題が発生します。

- **品質のばらつき**: 同じ指示でも実行のたびに異なる結果が生まれる
- **レビューの欠如**: AIが書いたコードが十分な検証なしにマージされる
- **並行作業の困難**: 複数プロジェクトの同時進行時、AIへの監視が人間のボトルネックになる
- **知識の散逸**: プロンプトやワークフローが属人的で共有できない

taktはこれらの課題に対し、**「AIに自由を与えるのではなく、仕組みとして行動を強制する」**という哲学で答えます。

### 音楽メタファによる直感的な設計

taktの名前は指揮棒（Taktstock）に由来します。オーケストラの指揮者が楽譜に基づいて演奏者を統制するように、taktはYAMLで定義されたワークフロー（**Piece** = 楽曲）に沿って、AIエージェント（**Persona** = 演奏者）の行動を各ステップ（**Movement** = 楽章）ごとに制御します。

```yaml
# Piece（楽曲）の一例: コードを書いてレビューするワークフロー
name: code-review
movements:
  - name: write-code      # 第1楽章: コード実装
    persona: coder
  - name: review           # 第2楽章: レビュー
    persona: supervisor
```

### taktの主要な特徴

| 特徴 | 説明 |
|---|---|
| **YAML駆動ワークフロー** | Piece（ワークフロー定義）をYAMLで記述し、チーム全体で共有・バージョン管理可能 |
| **マルチエージェント協調** | コーダー、レビュアー、セキュリティ審査員など、異なる役割のAIエージェントが連携 |
| **ルールベース遷移** | AIの判断ではなく、事前定義されたルールに基づいて次のステップを決定 |
| **並列実行** | 複数レビュアーの同時実行と結果の集約 |
| **完全なトレーサビリティ** | 全ステップのログをNDJSON形式で保存し、完全な監査証跡を提供 |
| **マルチプロバイダー** | Claude Code、OpenAI Codex、Cursor、Copilotなど複数のAIプロバイダーに対応 |
| **ファセットプロンプティング** | プロンプトを5つの独立した関心事に分離し、保守性と再利用性を確保 |
| **実践的な隔離** | git worktreeを活用してタスク実行を隔離し、作業中のコードを汚染しない |

### 基本的な使い方

```bash
# インストール
npm install -g takt

# 対話モードで起動
takt

# タスクを指定して起動
takt "認証機能を実装したい"

# GitHub Issueを指定
takt #99

# パイプラインモード（CI/CD連携）
takt --pipeline --task "バグを修正して" --auto-pr
```

### このサイトについて

このサイトでは、taktの全体像を以下の構成で解説します。

**背景と思想** — taktが生まれた背景と、その根底にある設計哲学を紐解きます。AIエージェント開発における「自由vs統制」の議論と、taktが選んだ「強制力による品質担保」の思想を深く掘り下げます。

**アーキテクチャ** — 7層に分かれた内部アーキテクチャ、Piece実行モデルの3フェーズ構造、ファセットプロンプティングによるプロンプト管理、マルチプロバイダー対応のエンジン設計を詳述します。

**利用方法** — インストールから実践的なカスタマイズまで、taktを使いこなすための具体的な手順とパターンを紹介します。25以上の組み込みペルソナと多様なPieceテンプレートの活用方法も網羅します。
